# Media Storage — provider atual Cloudflare R2

> Status: vigente
> Owner: integrations/media
> Última revisão: 2026-09-21
> Fonte de verdade: [ADR-0018](../adr/0018-portable-core-github-control-plane.md), [contrato de mídia](r2/README.md) e evidências operacionais datadas

## Papel do R2

Cloudflare R2 é o **provider atual** do Media Storage do TDA. O boundary permanente é Media Storage, não R2.

A regra arquitetural é:

- toda mídia persistida/publicada pertence ao Media Storage;
- Git não é storage canônico de mídia;
- PostgreSQL mantém identidades, relações e metadados de domínio;
- o object storage mantém os bytes;
- provider pode mudar sem redefinir lore, sessão, entidade ou consumidor;
- garantias de integridade, audience, read-back e rollback permanecem mesmo se o provider mudar.

Detalhes provider-neutral estão em [ADR-0018](../adr/0018-portable-core-github-control-plane.md). Detalhes de preparação/publicação estão no [fluxo único de mídia](r2/media-pipeline.md).

## Provider atual

### Buckets

| Papel lógico | Provider atual |
| --- | --- |
| mídia pública | `tda-media-public` |
| mídia privada/masters | `tda-media-private` |
| homologação/staging fora de Production | `tda-media-preview` |

Production pública usa:

`https://media.dnd.faysk.dev`

O domínio público é parte da entrega atual, não identidade do objeto. Consumers devem depender do registro/manifesto resolvido, não reconstruir URL pelo nome do personagem ou arquivo.

`r2.dev` permanece fora do contrato de Production. Buckets private/preview não ganham entrega pública por conveniência.

## Placement

### Media Storage

Devem convergir para Media Storage:

- imagens;
- backgrounds;
- portraits;
- artwork;
- gallery;
- mapas;
- social cards;
- áudio/vídeo que o produto decida persistir/publicar;
- assets de marca e demais binários de mídia.

Binários de mídia ainda versionados no Git são **compatibilidade/dívida de migração**, não precedente para conteúdo novo.

Áudio bruto/intermediários do fluxo de transcrição continuam fora da retenção cloud por ADR-0003. “Toda mídia no Media Storage” não transforma cache ou intermediário local descartável em artefato obrigatório de cloud.

### Git

O Git mantém:

- código;
- markup;
- manifests;
- metadata;
- SHA-256/MIME/bytes/provenance;
- migrations;
- tooling;
- documentação;
- configuração declarativa não secreta.

## Keys e integridade

A implementação atual usa keys content-addressed/imutáveis quando aplicável. Os contratos detalhados estão em:

- [identidade e keys](r2/identity-and-keys.md);
- [lifecycle](r2/lifecycle.md);
- [publicação e social](r2/publication-and-social.md);
- [segurança e custos](r2/security-and-costs.md).

Regras principais:

1. conteúdo novo recebe key nova;
2. não sobrescrever silenciosamente objeto content-addressed;
3. validar SHA-256, MIME e bytes do artefato enviado;
4. fazer read-back autenticado;
5. mídia pública exige GET HTTPS anônimo e verificação antes da promoção;
6. bucket/key/URL isolados não provam publicação;
7. rollback restaura referência anterior; não exige delete destrutivo do objeto.

## Credenciais

Credenciais S3 do provider atual são:

```text
R2_ACCOUNT_ID
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
```

`R2_PUBLIC_BUCKET` é configuração não secreta do destino atual.

Há dois boundaries:

- **operação/CI:** secrets usados por GitHub Actions pertencem preferencialmente ao GitHub Environment que executa a operação e usam credenciais separadas por bucket/finalidade;
- **runtime:** se a aplicação em execução realmente precisar acessar Media Storage, ela recebe somente a credencial server-side necessária naquele runtime.

Credenciais administrativas provisionadas em 2026-09-20:

```text
production public  -> tda-github-production-media-publisher
preview            -> tda-github-preview-media-publisher
production private -> tda-github-production-private-media-storage
```

Cada token Cloudflare está limitado a exatamente um bucket e Bucket Item Read + Write. O public foi comprovado em release real. Preview permanece provisionado sem consumidor automático. O candidato do **Lembra** agora referencia explicitamente o boundary privado de Production por `R2_PRIVATE_ACCESS_KEY_ID` / `R2_PRIVATE_SECRET_ACCESS_KEY`, mas esse runtime ainda não é considerado operacional até configuração, CORS/lifecycle e smoke controlados.

Vercel não é cofre intermediário para uma operação executada pelo GitHub Actions. Nenhum secret permanente chega ao browser.

Evidência administrativa sem valores: [R2 credential boundaries — 2026-09-20](evidence/r2-credential-boundaries-2026-09-20.json).

## Pipeline canônica

O fluxo para conteúdo versionado é:

```text
fonte aprovada
  -> identidade/role/audience
  -> hash/MIME/bytes/dimensões
  -> manifest
  -> Media Pipeline
  -> upload/reuso imutável
  -> read-back
  -> verificação pública quando aplicável
  -> receipt
  -> consumidor/referência
```

Implementação atual:

- manifests: `media/manifests/*.json`;
- pipeline: `tools/media/pipeline.mjs`;
- publisher de Production: `tools/ci/publish-production-media.sh`.

O repositório ainda contém fontes/binários de mídia de migrações anteriores sob `media/sources/` e outras áreas. Isso é estado transitório conhecido e deve convergir gradualmente para o boundary da ADR-0018; não remover destrutivamente enquanto existirem consumidores ou necessidade de recuperação.

## Custos

A política é free-first conforme ADR-0018.

R2 Standard é o provider/tier atual enquanto atende ao uso do TDA. Não habilitar Cloudflare Images, Stream, Infrequent Access ou outro serviço/tier pago por conveniência. Qualquer custo recorrente novo exige necessidade comprovada e decisão documentada.
